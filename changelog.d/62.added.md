Add the PostgreSQL answer to the core column-type protocol and the four new pad/repeat/trim nodes. `PostgresColumnTypeMixin` and `POSTGRES_COLUMN_TYPES` carry the protocol's closed list of eighteen common Python types with every entry measured: `list`/`tuple`/`set`/`frozenset` answer `ArrayColumn` (native arrays, measured on 9.6/12/18 with the whole guarantee set green — `INT[]` DDL, a Python list bound directly and read back, `array_length`, 1-based `x[1]`, containment `x @> ARRAY[v]`, concatenation, `v = ANY(x)`, whole-column equality and `unnest`), `dict` answers `JSONColumn` while the DDL layer chooses `jsonb` through the `DataType` layer, `enum.Enum` answers `StringColumn`, and `float`/`decimal.Decimal` answer `NumericColumn` now that core removed `FloatColumn`/`DecimalColumn`/`RealColumn`/`DoubleColumn` and the numeric family is deliberately one class. `datetime.timedelta` is refused on purpose: PostgreSQL spells it `interval`, but no core column class names an interval's operations, and the previous `NumericColumn` answer offered `sqrt(interval '1 day')` for the engine to refuse at execution — a field declared `timedelta` now fails to resolve with a message naming the fix (`UseColumnType`). `PostgresDialect` composes the generic `TrimMixin`/`LpadMixin`/`RpadMixin`/`RepeatMixin` with no override, because PostgreSQL spells all four natively (`TRIM([BOTH|LEADING|TRAILING] [chars] FROM str)`, `LPAD`/`RPAD(str, len, padstr)`, `REPEAT(str, n)`). `PostgresUUIDMixin` and `PostgresUUIDAdapter` state the version-13-built-in-or-uuid-ossp answer and win over the core adapter's single fixed spelling, and `supports_uuid_ossp_extension` names the narrower question of whether uuid-ossp is installed.
