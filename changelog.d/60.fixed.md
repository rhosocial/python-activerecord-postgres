Forward SSL/TLS connection parameters to the driver. `PostgresBackend.connect()` and `AsyncPostgresBackend.connect()` read `ssl_ca`/`ssl_cert`/`ssl_key`/`ssl_mode`, but `PostgresConnectionConfig` inherits only the libpq-named `PostgresSSLMixin` (`sslmode`/`sslcert`/`sslkey`/`sslrootcert`/`sslcrl`/`sslcompression`) and not the generic `SSLMixin`, so every `hasattr()` check was `False` and no TLS setting ever reached `psycopg.connect()`. Connections therefore ran unencrypted even with `sslmode="verify-full"`, and an unreadable `sslrootcert` was silently ignored. The shared `PostgresConnectionConfig.get_ssl_connection_params()` now collects the configured libpq keywords once for both the sync and async paths, and the kwargs extraction lists in both backends accept the libpq names instead of the generic ones.
