Make partition-scheme change suggestions safe to consume: abandoning a scheme no longer returns a data-destroying `DROP TABLE`, and adopting one no longer returns a bare `PARTITION BY` clause that cannot execute on its own. Both now report explicitly unsupported; removing partitioning requires a separately authorized data-preserving rebuild. A structural test pins that no change-point answer chain contains destructive DDL.
Fix `list_sequence_states()` on a live server: `pg_depend.classid` and `pg_depend.refclassid` are `oid`-typed, and the ownership join compared them to the bare text `'pg_class'`, which PostgreSQL refuses with `invalid input syntax for type oid`. Scripted rows answered each scripted marker, so the family looked covered while no real server could answer it. Both comparisons now resolve the catalogue name through `regclass` (`'pg_catalog.pg_class'::regclass`, spelled schema-qualified so `search_path` cannot redirect it), an offline guard pins the corrected spelling and rejects the bare one, live tests read an owned `serial` sequence, an owned identity sequence and an unowned one, and an unowned sequence reports `owned_by=None` rather than the empty string `concat_ws` yields when all its arguments are NULL.
